    Plugins, skills, MCP

    Wie installeert wat?

    Niet alles kan Claude zelf installeren. Elke tool in de library heeft een label dat zegt wie wat doet. De CLAUDE.md uit de stack-bouwer zet dit per stap op een rij, met een prompt die je aan Claude kunt geven.

    npmskillregels

    Claude doet het zelf

    Packages (npm), frameworks en componenten installeert Claude in je project. Skills installeert Claude met npx skills add eigenaar/repo, of zet de map met een SKILL.md zelf in .claude/skills/. Die worden direct opgepikt; bestond de map nog niet, typ dan /reload-skills.

    MCP

    Claude bereidt voor, jij keurt goed

    Voeg een MCP-server toe met claude mcp add … in je terminal, of laat Claude hem in .mcp.json zetten. Claude Code vraagt jou om goedkeuring. Servers met een login (Figma, Vercel, Supabase) koppel je via /mcp.

    plugin

    Jij installeert

    Plugins installeer je zelf met /plugin in Claude Code (eerst /plugin marketplace add … als ze niet in de officiële marketplace staan). Start daarna een nieuwe sessie. Een cloudsessie op claude.ai/code laadt je lokale plugins niet.

    account

    Jij maakt een account

    Diensten zoals Supabase, Vercel, Clerk of Sentry vragen een account. Zet de keys in .env.local en nooit in git. Claude schrijft daarna de code die ze gebruikt.

    site

    Geen installatie

    Inspiratie, kleuren, fonts en checkers gebruik je gewoon in je browser. Geef Claude screenshots of kopieer de waarden.

    Zet het gegenereerde bestand als CLAUDE.md in de root van je project. Claude Code leest het automatisch bij elke sessie, dus je stack, regels en aandachtspunten zijn vanaf de eerste prompt bekend.

    CLAUDE.md
    
        
    Liever zelf? Zet CLAUDE.md in de root en de doc-bestanden in een map docs/. Tip: begin je eerste prompt met "Lees CLAUDE.md en stel eerst vragen als iets onduidelijk is." Werk het bestand bij als je stack verandert.
    
      
    
    
    
  
    

  
    
    
    
      Uit het Google Doc
      
    De .md-starterkit voor vibe coders
    
      
    AI-tools schrijven snel code, maar raden zonder projectregels. Zet vier Markdown-bestanden in een /docs-map en laat je AGENTS.md (of CLAUDE.md) naar ze verwijzen. Dan leest de agent eerst de regels voordat hij iets bouwt.
    
      
    my-app/
├── app/
├── components/
├── lib/
└── docs/
   ├── PRD.md
   ├── AGENTS.md
   ├── DESIGN_SYSTEM.md
   ├── ARCHITECTURE.md
   ├── SECURITY.md
   ├── CODE_STYLE.md
   ├── DATABASE.md
   └── API.md
    
      
    Werkwijze uit de gids
        
      
          
    • Begin met de voorbeeldbestanden en vervang placeholders door je echte stack.
      • 
          
    • Laat de agent het relevante .md-bestand lezen vóór een feature.
      • 
          
    • Werk de docs bij zodra de code verandert.
      • 
          
    • Documenteer wat je écht gebruikt: Supabase óf Firebase, niet allebei "voor de zekerheid".

    SECURITY.md
    Hoe het project gebruikers, data en secrets beschermt.
    
        
    1. Auth & autorisatie (sessie op de server checken)
    2. Secrets & env-variabelen
    3. Input-validatie
    4. API-beveiliging

    AI-agent regels (uit SECURITY.md)
        
      
          
    • Verzin of hardcode nooit productie-credentials.
      • 
          
    • Zet authenticatie nooit uit om iets werkend te krijgen.
      • 
          
    • Omzeil nooit autorisatiechecks.
      • 
          
    • Zet nooit secrets in client-side code.
      • 
          
    • Vraag om verduidelijking als een wijziging botst met dit bestand.
